title: Network Integration
description: How to implement a custom network proxy that integrates with minecraft-gateway using the NetworkXDS gRPC stream.
---

minecraft-gateway separates edge routing (hostname matching) from network routing (which game server a player belongs on). The network proxy handles the connection to the player; the **controller** decides where each player goes.

Proxies connect to the controller over a persistent bidirectional gRPC stream — **NetworkXDS** — and the two exchange messages for as long as the proxy lives.

The built-in integration uses [Velocity](https://papermc.io/software/velocity). This guide explains how to implement your own.

## Prerequisites

- Your proxy runs as a Kubernetes Deployment managed by the controller (via `networkTemplate`)
- Your proxy can make gRPC calls to the controller's network server

## Why the controller decides

Each proxy only sees its own players. If every proxy picked servers on its own, a burst of players routed at once would send them all to whichever server looked emptiest to everyone at the same moment, and overload it.

The controller sees every proxy at once, and counts decisions it has already handed out but that have not yet arrived. Your proxy therefore reports what it observes and applies what it is told, rather than choosing servers itself.

## How it works

When a Gateway listener is reconciled, the controller creates a Deployment and Service for your proxy from `networkTemplate`, and injects the environment variables your proxy uses to find and identify itself to the controller.

Your proxy then opens the stream and keeps it open:

1. Send `ProxyHello` identifying yourself, then a `PresenceSnapshot` replaying every player you currently hold.
2. Apply `ServerSync` messages, which carry the full set of servers you should have registered.
3. Send a `RouteRequest` whenever a player joins or needs a fallback, and connect them to the server named in the matching `RouteResponse`.
4. Send `PlayerPresenceEvent` as players connect to and disconnect from backend servers.
5. Execute `MoveCommand` messages and reply with a `MoveResult`.

## Environment variables

The controller injects these environment variables into every network proxy container:

| Variable | Description |
|---|---|
| `NAMESPACE` | Kubernetes namespace of the Gateway |
| `GATEWAY_NAME` | Name of the Gateway |
| `LISTENER_NAME` | Name of the listener this proxy serves |
| `GATEWAY_NETWORK_XDS_HOST` | Hostname of the NetworkXDS gRPC server |
| `GATEWAY_NETWORK_XDS_PORT` | Port of the NetworkXDS gRPC server (default: `19000`) |

Kubernetes also sets `HOSTNAME` to the pod name, which the built-in integration uses as its proxy id.

## The NetworkXDS API

```protobuf
service NetworkXDS {
  rpc Connect(stream ProxyMessage) returns (stream ControllerMessage);
}

message ProxyMessage {
  oneof message {
    ProxyHello hello = 1;
    PresenceSnapshot presence_snapshot = 2;
    RouteRequest route_request = 3;
    PlayerPresenceEvent presence_event = 4;
    ServerPlayerCounts player_counts = 5;
    MoveResult move_result = 6;
  }
}

message ControllerMessage {
  oneof message {
    ServerSync server_sync = 1;
    RouteResponse route_response = 2;
    MoveCommand move = 3;
  }
}
```

### Opening the stream

`ProxyHello` **must** be the first message. Send `PresenceSnapshot` immediately after it.

```protobuf
message ProxyHello {
  string proxy_id = 1;           // stable per pod; use HOSTNAME
  string gateway_namespace = 2;  // NAMESPACE
  string gateway_name = 3;       // GATEWAY_NAME
  string listener_name = 4;      // LISTENER_NAME
}

message PresenceSnapshot {
  repeated PresenceEntry players = 1;
}

message PresenceEntry {
  string player_uuid = 1;
  string server_name = 2;
  PlayerContext context = 3;
}
```

The controller keeps presence in memory only. Replaying it on every connect is what lets it recover after a restart or a leader failover, so the replay is required, not an optimization.

Reconnecting with the same `proxy_id` replaces the earlier session.

### Registering servers

```protobuf
message ServerSync {
  repeated ManagedServer servers = 1;
  repeated string required_permissions = 2;
}

message ManagedServer {
  string unique_id = 1;
  string name = 2;
  string ip = 3;
  uint32 port = 4;
  optional uint32 numerical_id = 5;
  optional uint32 max_players = 6;
  optional uint32 current_players = 7;
}
```

`ServerSync` always carries the **complete** set of servers, not a delta. Diff it against what you have registered: register anything new or changed, unregister anything absent. One is sent as soon as you connect, and again whenever the configuration changes.

`required_permissions` is described under [Routing decisions](#routing-decisions).

### Routing decisions

```protobuf
message RouteRequest {
  string correlation_id = 1;
  string player_uuid = 2;
  RouteKind kind = 3;                     // ROUTE_KIND_JOIN or ROUTE_KIND_FALLBACK
  PlayerContext context = 4;
  optional string current_server_name = 5;  // for fallbacks
}

message PlayerContext {
  string connected_domain = 1;
  map<string, bool> permissions = 2;
}

message RouteResponse {
  string correlation_id = 1;
  Result result = 2;        // RESULT_OK, RESULT_NO_ROUTE, RESULT_REJECTED
  string server_name = 3;
}
```

Match the response to the request by `correlation_id`; responses may arrive in any order.

Routing rules can test permissions, which only your proxy can evaluate. So the controller tells you which permissions it needs via `required_permissions`, and you send the results in `context.permissions` with every `RouteRequest` and every `KIND_CONNECTED` presence event. Evaluate exactly the permissions you were asked for.

On `RESULT_OK`, connect the player to `server_name`. On any other result, disconnect them with a suitable message.

<Warning>
While the stream is down, reject joins instead of routing them yourself. Routing against a stale local view is exactly what overloads servers during a mass reconnect. Reconnect with exponential backoff.
</Warning>

### Reporting presence

```protobuf
message PlayerPresenceEvent {
  string player_uuid = 1;
  string server_name = 2;
  Kind kind = 3;              // KIND_CONNECTED or KIND_DISCONNECTED
  PlayerContext context = 4;
}
```

Send `KIND_CONNECTED` once a player has actually reached a backend server, and `KIND_DISCONNECTED` when they leave your proxy. These events are what keep the controller's player counts accurate, so routing decisions and the [player query API](/concepts/overview#player-query-api) stay correct.

You may also send `ServerPlayerCounts` periodically; the controller uses it to detect drift.

### Executing moves

```protobuf
message MoveCommand {
  string command_id = 1;
  string player_uuid = 2;
  string server_name = 3;
}

message MoveResult {
  string command_id = 1;
  bool success = 2;
  string reason = 3;
}
```

`MoveCommand` carries out a [PlayerTransfer](/reference/player-transfer). Look the player up by UUID, connect them to the named server, and always reply with a `MoveResult` carrying the same `command_id` — the transfer's status waits on it. Use `player_not_found`, `server_not_registered`, or `connect_failed` as the failure `reason`.

## Deploying your proxy

Use `networkTemplate` in `NetworkInfrastructure` to deploy your proxy image:

```yaml
apiVersion: gateway.networking.minefleet.dev/v1alpha1
kind: NetworkInfrastructure
metadata:
  name: my-infrastructure
  namespace: default
spec:
  discovery:
    namespaceSelector:
      from: Same
    labelSelector:
      matchLabels:
        minefleet.dev/gameserver: "true"
  networkTemplate:
    template:
      spec:
        containers:
          - name: network
            image: ghcr.io/your-org/your-proxy:latest
```

The controller creates one Deployment per listener and injects the environment variables above. Your image should read them at startup to connect to the controller.

See [Customizing the Network Proxy](/guides/customizing-network-proxy) for additional `networkTemplate` options such as mounting secrets and setting resource limits.

## Using the Java integration-api

If you are writing a JVM-based proxy plugin, the `integration-api` library wraps the raw gRPC stream and handles reconnects, server diffing, and correlation for you. The Velocity built-in integration is implemented using it.

### Implement `ServerRegistrar`

`ServerRegistrar` is called whenever backend servers appear, update, or disappear. Use `server.name()` as the stable key in your proxy's server registry.

```java
import dev.minefleet.api.gateway.networking.ManagedServer;
import dev.minefleet.api.gateway.networking.ServerRegistrar;
import dev.minefleet.api.gateway.networking.ServerRegistrarException;

import java.net.InetSocketAddress;
import java.util.Optional;
import java.util.concurrent.ConcurrentHashMap;

public class MyServerRegistrar implements ServerRegistrar {

    private final MyProxy proxy;
    private final ConcurrentHashMap<String, ManagedServer> servers = new ConcurrentHashMap<>();

    public MyServerRegistrar(MyProxy proxy) {
        this.proxy = proxy;
    }

    @Override
    public void registerOrUpdate(ManagedServer server) throws ServerRegistrarException {
        try {
            var address = new InetSocketAddress(server.ipAddress(), server.port());
            if (!proxy.hasServer(server.name())) {
                proxy.registerServer(server.name(), address);
            }
            servers.put(server.name(), server);
        } catch (Exception e) {
            throw new ServerRegistrarException(server, e);
        }
    }

    @Override
    public void unregister(ManagedServer server) throws ServerRegistrarException {
        try {
            proxy.unregisterServer(server.name());
            servers.remove(server.name());
        } catch (Exception e) {
            throw new ServerRegistrarException(server, e);
        }
    }

    @Override
    public Optional<ManagedServer> findByName(String name) {
        return Optional.ofNullable(servers.get(name));
    }
}
```

Throw `ServerRegistrarException` to signal a failure for a single server. The library retries failed servers up to `retries` times (default: 3).

### Implement `NetworkPlayer`

`NetworkPlayer` is a per-event wrapper. Create a new instance for each routing call.

```java
import dev.minefleet.api.gateway.networking.ManagedServer;
import dev.minefleet.api.gateway.networking.player.KickReason;
import dev.minefleet.api.gateway.networking.player.NetworkPlayer;

import java.util.Optional;
import java.util.UUID;

public class MyNetworkPlayer implements NetworkPlayer {

    private final MyPlayer player;
    private final MyServerRegistrar registrar;

    public MyNetworkPlayer(MyPlayer player, MyServerRegistrar registrar) {
        this.player = player;
        this.registrar = registrar;
    }

    @Override
    public UUID getUuid() {
        return player.getUniqueId();
    }

    @Override
    public String getConnectedDomain() {
        // The virtual hostname from the Minecraft handshake
        return player.getVirtualHost().getHostString();
    }

    @Override
    public Optional<ManagedServer> getConnectedServer() {
        return player.getCurrentServer()
            .flatMap(s -> registrar.findByName(s.getName()));
    }

    @Override
    public boolean hasPermission(String permission) {
        return player.hasPermission(permission);
    }

    @Override
    public void connectToServer(ManagedServer server) {
        proxy.getServer(server.name())
            .ifPresent(s -> player.connect(s));
    }

    @Override
    public void kick(KickReason reason) {
        String message = switch (reason) {
            case NO_JOIN -> "No server is available.";
            case NO_FALLBACK -> "No fallback server is available.";
            case ROUTING_UNAVAILABLE -> "The network is temporarily unavailable.";
        };
        player.disconnect(message);
    }
}
```

### Build and start `NetworkGateway`

Build one `NetworkGateway` at proxy startup. The builder reads the injected environment variables automatically.

```java
import dev.minefleet.api.gateway.networking.NetworkGateway;

public class MyProxyPlugin {

    private NetworkGateway gateway;
    private MyServerRegistrar registrar;

    public void onEnable() {
        // Remove statically configured servers — the gateway is the sole source of truth
        proxy.getServers().forEach(s -> proxy.unregisterServer(s.getName()));

        registrar = new MyServerRegistrar(proxy);
        gateway = NetworkGateway.builder()
            .registrar(registrar)
            // Replayed to the controller on every (re)connect
            .presenceSupplier(this::currentPresence)
            .build();

        // Needed so move commands can find a player by UUID
        gateway.setPlayerLookup(uuid -> proxy.getPlayer(uuid)
            .map(p -> new MyNetworkPlayer(p, registrar)));

        gateway.start();
    }

    public void onDisable() {
        gateway.stop();
    }

    private List<Api.PresenceEntry> currentPresence() {
        return proxy.getAllPlayers().stream()
            .flatMap(p -> p.getCurrentServer().stream()
                .map(s -> gateway.presenceEntry(new MyNetworkPlayer(p, registrar), s.getName())))
            .toList();
    }
}
```

### Wire routing and presence events

`routeJoin` and `routeFallback` return a `CompletableFuture` that completes once the controller has answered and the player has been connected or kicked. Where your proxy supports it, defer the event until that future completes rather than blocking the event thread.

```java
// Player connects for the first time
public void onPlayerJoin(PlayerJoinEvent event) {
    gateway.routeJoin(new MyNetworkPlayer(event.getPlayer(), registrar));
}

// Player was kicked from a server and needs a fallback
public void onPlayerKicked(PlayerKickedEvent event) {
    gateway.routeFallback(new MyNetworkPlayer(event.getPlayer(), registrar));
}

// Player reached a backend server
public void onServerConnected(ServerConnectedEvent event) {
    gateway.reportConnected(new MyNetworkPlayer(event.getPlayer(), registrar), event.getServerName());
}

// Player left the proxy
public void onPlayerDisconnect(PlayerDisconnectEvent event) {
    gateway.reportDisconnected(event.getPlayer().getUniqueId());
}
```

Reporting presence is not optional: the controller routes from these events, so a proxy that does not report them will be routed against as though it were empty.

If the controller is unreachable, both routing methods kick the player with `ROUTING_UNAVAILABLE` instead of guessing. Check `gateway.isReady()` if you want to handle that case yourself.

### `ManagedServer` field reference

| Method | Type | Description |
|---|---|---|
| `name()` | `String` | Stable server name — use as the key in your proxy registry |
| `ipAddress()` | `String` | IP address to connect to |
| `port()` | `int` | Port to connect to |
| `uniqueId()` | `String` | Globally unique identifier for this server instance |
| `numericalId()` | `OptionalInt` | Optional numerical slot ID |
| `maxPlayers()` | `OptionalInt` | Configured player capacity |
| `currentPlayers()` | `OptionalInt` | Player count as last known to the controller |

### `NetworkGateway.Builder` options

| Method | Default | Description |
|---|---|---|
| `registrar(ServerRegistrar)` | — (required) | Your `ServerRegistrar` implementation |
| `presenceSupplier(Supplier)` | empty | Players to replay to the controller on every (re)connect |
| `retries(int)` | `3` | Retry attempts for failed `registerOrUpdate`/`unregister` calls |
| `context(NetworkContext)` | from env | Proxy id and the gateway/listener served |
| `channel(Channel)` | from env | gRPC channel to the controller |
